# MM05: Event-log import and export

## Question

Can a compact saved command stream reproduce finite-depth execution fills and
account totals without regenerating a market path? The applied baseline is the
existing direct in-memory parent-execution engine. The comparison covers TWAP
and Sweep + retry, both buy and sell parents, rising paths and capacity limits.

## Method

`src/event_log.py` defines a versioned UTF-8 JSON contract with compact array
rows for accepted submissions and owner-authorized full cancellations. Every
command has a contiguous sequence; order IDs count submissions only. Replay
starts with an empty instance of the public matching engine and computes trades
from commands. No random draws, quoting policy or supplied fill instructions
participate in replay. The [format document](../docs/event-log.md) specifies
types, fees, sequence rules, checkpoints and validation failures.

The fee header uses exact integer minor units. Here only the parent pays
5 hundredths of a tick per actual executed unit; background and external owners
pay zero. Gross cash remains the book's existing integer ledger. Reconstructed
accounts also expose exact fees and net cash. Fees are an external sink; funding
and borrow charges are zero. Parent residual quantity is not filled inventory.

Four synthetic seeds, 500 through 503, each supply three scenarios: balanced
120-unit parents, rising 120-unit parents and balanced 700-unit capacity stress.
Each is evaluated with both sides and both policies, for 48 runs. Recording
enabled versus disabled must produce identical existing execution results.
The exported log is serialized and decoded before replay. Every trade and
resting FIFO order plus all account totals must match the original checkpoint.
Parent fill sequence, gross cash, net cash, inventory, fees and reconstructed
arrival-price shortfall are also compared with the direct baseline. Shortfall
uses separately retained arrival midpoint, terminal midpoint and parent size;
these are valuations and intent, not reconstructible book commands.

The recorded example is a real saved file read from disk on each experiment
run, not merely a round trip of a live object. It must match a newly recorded
seed-1729 balanced TWAP run. Its identical studio copy is checked by a test.
Checksums cover the stream and the reconstructed complete ledger, using the
explicit serialization convention in the format document. They do not establish
authenticity against a writer who can replace both data and checksums.

## Reproduce

```bash
python -m src.event_log --export-example examples/twap-events.json
python -m src.event_log --replay examples/twap-events.json --out results/replayed-example.json
python -m unittest discover -s tests -v
python lab.py --output results/latest.json
python src/studio.py --out docs/study.json
python src/studio.py --check docs/study.json
python quality/contract.py --project . --name market-microstructure-lab --task-id MM05
```

The example export is deterministic. The studio bundles the same bytes as
`docs/twap-events.json`; regenerate that copy with `--export-example
docs/twap-events.json` when intentionally changing the example. Serve the
studio as described in README and choose **Event log / audit** for the measured
comparison, overlapping direct/replayed shortfall traces, ledger CSV and saved
log/format downloads. Browser charts display recorded evidence; Python performs
validation and replay.

## Actual findings

The 48 comparisons process **11,019 commands and 2,035 trade records**, with
**zero fill, account or shortfall mismatches**. Recording also leaves every
existing execution result unchanged. These are equality checks on a fixed
synthetic sample, not statistical estimates or a throughput benchmark. Negative
shortfalls and incomplete capacity-stress parents remain in the raw table.

The saved example contains **243 commands**, **32 total trade records** and
**9 resting orders**, occupying **8,464 UTF-8 bytes** including its final newline.
Its 20 parent fill records execute 120 units. Direct and imported outcomes are:

| Outcome | Direct | Saved-stream replay |
| --- | ---: | ---: |
| Parent gross cash / ticks | -1,200,010 | -1,200,010 |
| Executed inventory / units | 120 | 120 |
| Fees / ticks | 6 | 6 |
| Net cash / ticks | -1,200,016 | -1,200,016 |
| Arrival-price shortfall / ticks | 16 | 16 |

This account intentionally retains acquired inventory: execution is not the
market-making liquidation study. Replaying the final cash alone would miss that
120-unit asset and would misstate execution cost. The original negative policy
results in earlier studies remain reproducible and unchanged.

All 47 tests pass. New checks include a hand-computed partial-fill/FIFO example
with a cancelled middle order; exact fee-sink conservation; self-trades; empty
streams; integer balances beyond binary64 precision; 600 randomized live-book
commands including cancellations; malformed JSON and duplicate keys; invalid
types, sequence and ownership; and corruption/checkpoint disagreement even when
the outer checksum is recomputed. Existing independent list-oracle matching tests
remain part of the full suite.

## Limitations

The stream records accepted commands, not exchange traffic: pending messages,
send/arrival timestamps, reference marks, parent intent and strategy state are
omitted. It reconstructs the book ledger, not the entire latency or policy
process. The fee scale is explicit; the execution adapter logs only rates in
exact hundredths, while the generic log supports another integer scale.
Python preserves arbitrary integers; other consumers must avoid rounding them.

All orders and prices are synthetic, with five finite levels and full background
replenishment each batch. Self-trades and unlimited credit/shorting are allowed.
There is no calibration, historical feed import, live trading claim, persistent
impact model, or production latency/throughput evidence. Replay uses the same
matching engine as direct execution and cannot independently establish exchange
correctness. The hashes detect accidental changes and mismatched reconstruction,
not forgery. Import/export correctness here does not imply a market edge.

The wire syntax reference is the primary
[JSON standard, RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html), verified
against the RFC Editor source. This custom schema is intentionally stricter than
general JSON and is not a standard exchange feed.

## What the author should understand for an interview

Trace how command sequence differs from submission ID and why a cancelled middle
order cannot move surviving makers forward relative to one another. Explain why
fills must be recomputed, how a checkpoint differs from an instruction, and why
a checksum is not authentication. Reconcile gross zero-sum cash, signed inventory,
the external fee sink and net cash in integer units, including both self-trade
legs. Explain why a filled buy parent is not a flat account, why residual intent
is not inventory, and which marks are additionally needed for shortfall. Separate
deterministic reproduction from independent matching correctness and real-market
validity, and identify what additional messages/state a latency replay would need.
